Domain Verification Setup

Step-by-step visual instructions for setting up DNS records on every major hosting provider.

How DNS-01 verification works

When you request a certificate, our server gives you a random token. You add that token as a TXT record under _letssecure-challenge.yourdomain.com. Our server then queries your DNS. If the token matches, the certificate is issued.

1

Get your TXT record values

Request a certificate from the Home page. You'll get a Name and Value — keep them handy. They look like this:

Type TXT
Name _letssecure-challenge.example.com
Value ls-verify-a3f8b2c9d4e5f6a7b8c9d0e1f2a3b4c5

3

Verify from your terminal

Before clicking Verify Now in the app, confirm your DNS record is publicly visible.

Terminal
# Query the authoritative resolver
$ nslookup -type=TXT _letssecure-challenge.example.com 1.1.1.1

# Expected output:
Server: 1.1.1.1
Address: 1.1.1.1#53

Non-authoritative answer:
_letssecure-challenge.example.com text = "ls-verify-a3f8b2c9d4e5…"

# Or with dig:
$ dig TXT _letssecure-challenge.example.com +short
💡 If you see the token, click Verify Now in the Home page. If you don't, wait 5–30 minutes and try again.
?

Common issues

"No TXT record found"

Either the record isn't saved, or DNS hasn't propagated yet. Wait 15–30 min and re-verify with nslookup.

"Token mismatch"

The record exists but has the wrong value. Copy the token exactly, with no spaces or line breaks.

Record has quotes

Some providers auto-add quotes. Our server strips them — no action needed.

Propagation is slow

Some ISPs cache DNS for hours. Try nslookup … 1.1.1.1 to query Cloudflare directly.

FreeDNS won't allow TXT

Switch to HTTP-01 method, or move the domain to Cloudflare (free) which fully supports TXT.

Wildcard domain requested

Wildcards (*.example.com) require DNS-01. HTTP-01 and TLS-ALPN-01 don't support them.

How HTTP-01 verification works

Our server requests a specific file from your web server at http://yourdomain.com/.well-known/letssecure-challenge/<token>. If the file exists and its content matches, the certificate is issued.

1

Get the file path and content

Request a certificate from the Home page and select HTTP-01 as the method.

Path /.well-known/letssecure-challenge/a3f8b2c9d4e5f6a7
Content ls-verify-a3f8b2c9d4e5f6a7b8c9d0e1f2a3b4c5
URL http://example.com/.well-known/letssecure-challenge/…
2

Create the file on your web server

Choose your server type below for exact instructions.

NX

Nginx

Most popular web server

  1. 1
    Create the directory

    SSH into your server and run:

  2. 2
    Write the token to a file

    Use tee or echo to write the exact content.

  3. 3
    Configure Nginx to serve it

    Add a location block to your site config.

Shell
$ sudo mkdir -p /var/www/html/.well-known/letssecure-challenge/
$ echo "ls-verify-a3f8b2c9d4e5…" | sudo tee \
/var/www/html/.well-known/letssecure-challenge/a3f8b2c9d4e5f6a7
nginx.conf
# Inside your server block:
location /.well-known/letssecure-challenge/ {
  root /var/www/html;
  default_type text/plain;
  add_header Cache-Control "no-store";
}
Reload
$ sudo nginx -t && sudo systemctl reload nginx

How TLS-ALPN-01 verification works

Our server performs a TLS handshake with your server on port 443 using the acme-tls/1 ALPN protocol. Your server must present a specific temporary certificate that contains the challenge token in an acmeIdentifier extension.

⚠

Before you start

TLS-ALPN-01 is advanced. Stock Nginx, Apache, and most shared hosting do NOT support custom ALPN protocols. Only use this method if you're running Caddy, Nginx Plus, or a custom TLS server.

Alternative: Use DNS-01 or HTTP-01 instead — they work everywhere.
1

Download the provisioning files

After requesting a certificate with TLS-ALPN-01, you'll get two files.

Cert example.com-provision.crt.pem
Key example.com-provision.key.pem
2

Install on your server

CD

Caddy

Native ALPN support

Caddy supports ALPN out of the box. Add a dedicated listener on 443.

Caddyfile
example.com:443 {
  tls /etc/caddy/provision.crt.pem /etc/caddy/provision.key.pem
  protocols tls1.2 tls1.3
  respond "ok"
}
Reload
$ sudo systemctl reload caddy
NX+

Nginx Plus

Commercial Nginx — custom ALPN

nginx.conf
server {
  listen 443 ssl;
  server_name example.com;
  ssl_certificate /etc/nginx/provision.crt.pem;
  ssl_certificate_key /etc/nginx/provision.key.pem;
  ssl_alpn "acme-tls/1";
}
⚠️ Stock open-source Nginx does not support ssl_alpn.
N

Node.js (custom TLS)

Programmatic control

tls-server.js
const tls = require("tls");
const fs = require("fs");

tls.createServer({
  cert: fs.readFileSync("provision.crt.pem"),
  key: fs.readFileSync("provision.key.pem"),
  ALPNProtocols: ["acme-tls/1"],
}, (socket) => socket.end());
.listen(443);
3

Verify from your terminal

Terminal
$ openssl s_client -connect example.com:443 \
-servername example.com -alpn acme-tls/1 < /dev/null 2>/dev/null | \
grep -i "ALPN"

ALPN protocol: acme-tls/1
✅ If you see ALPN protocol: acme-tls/1, you're ready. Click Verify Now in the Home page.
